Warmpath — Build Spec

Working name. Meta Global AI Developer Hackathon (Cerebral Valley), Indie track. Deadline Wed Nov 4, 2026, 9:00 PM EST. Spec written Sun Nov 1 from Alix's design discussions; update the Open Questions section after the Mon Nov 2 user conversation.

1. Context and goal

  • Hackathon: remote, very large field (up to ~20,000 entrants), judged Nov 4–8. Indie track values creativity, technical ambition, and whether it works. First-pass judging will likely look at the first 30 seconds of the video and the README. Theme fit: "Build for Your World" — Alix does founder–investor connection work at a university venture center.
  • Second purpose: a credible prototype for a Network Intelligence internship (a hub that connects founders from emerging markets to Bay Area investors, operators and AI builders, with a Salesforce-based network model). The product must stay generic — no real organization's name or branding.
  • Resume purpose: every claim must be true and defensible.

2. Problem

The primary user is hub staff: people whose organization's product is its network. Their network lives in a few heads, inboxes and spreadsheets. Four concrete pains:

  1. Capture. Nobody fills in the CRM after a coffee chat. Data starts rotting on day one.
  2. Recall. Who knows whom, what an investor said last time ("we stopped doing B2C") depends on memory. When staff leave, that part of the network leaves with them.
  3. Execution. Intro emails, double opt-in, scheduling and follow-up are repetitive manual work. A visiting founder may need 10–15 meetings coordinated within one week.
  4. Proving value. A nonprofit hub has to show its board and funders that connections produced funding and hires. Without recorded outcomes this cannot be shown.

Capture, recall and execution are the core. Attention budgeting is a visible constraint, not the headline: at single-hub scale staff can allocate by judgment; it matters more when several hubs share the same investors.

Two-sided attention (design principle)

  • Investor attention is a constraint. It is the hub's trust capital. Each ask spends credibility; it recovers slowly. Model: rolling 30-day ask count per investor with a cap (default 2). Over cap → excluded or shown greyed with reason.
  • Founder attention is a cost in the objective. Visiting founders have a hard time window (e.g. 10 days in the Bay Area) and limited meetings per day. A bad-fit meeting costs prep time, meeting time and morale. The planner maximizes expected value per founder-hour within the window.

4. Demo storyline — "A founder's Bay Area week"

The 2-minute video follows one workflow end to end. The first 15 seconds must show something visual happening, not a title card.

  1. Capture (0:00–0:30). Drop a business-card image + a forwarded email + a 30-second voice memo. Graph view: a new node appears, an edge lights up, a fact chip ("only leads seed/A, no B2C since 2026") attaches with its source.
  2. Visit request (0:30–0:50). "Fintech founder from Lagos, raising Series A, needs a lead + a payments operator, in SF Nov 10–19."
  3. Plan (0:50–1:25). Candidates with reasons and citations. One investor shown greyed: "asked 3× this month." One excluded by a fact stated 4 months ago. The 10-day calendar fills: operators early, lead investors after. Double opt-in drafts and founder briefs appear.
  4. Outcomes (1:25–1:45). Mark outcomes; dashboard funnel updates.
  5. Eval (1:45–2:00). One slide: matching precision@3 and long-horizon memory recall numbers.

7. Modules and acceptance criteria

M0API smoke test

Script that calls each model once: Spark with text, image and PDF; transcribe with a short audio file; Wonder with a long-context prompt; Image with one prompt. Record latency, token counts, structured-output support. Done when all four succeed or a blocking limitation is written in docs/STATUS.md.

M1Synthetic network

~300 people (≈60 founders across Lagos, São Paulo, Jakarta, Mexico City, Nairobi, Cairo, etc.; ≈120 investors; ≈80 operators; ≈30 builders; ≈10 staff), ~1,500 interactions spread over 18 months, edges derived from interactions. Seeded and reproducible. Plant: (a) 20 visit scenarios with hand-specified ground-truth best intros, (b) ~30 "needle" facts stated early and later contradicting naive matches (e.g. an investor who stopped doing B2C), (c) a few investors already over the ask cap. Done when make seed builds the DB and ground truth file deterministically.

M2Capture pipeline

Endpoint accepts image / PDF / pasted email / audio. Audio → transcribe → text. Spark returns structured ProposedDiffs with confidence; every Fact links its source Interaction. Entity resolution against existing Persons (name + org fuzzy match; ask when ambiguous). Done when the three demo inputs produce correct pending diffs and accepting them updates the graph.

M3Memory and recall

Two recall modes behind one interface: (A) retrieval — filter Facts by subject/tags, pass top-k to Spark; (B) full history — the relevant people's full interaction history in Wonder's context, with caching. Facts can be superseded; the newest non-superseded statement wins and both are shown. Done when a query about a needle-fact investor returns the correct current stance with citation in both modes.

M4Visit planner

  • Candidate scoring: fit (Wonder judgment over needs + profile + facts, must cite fact IDs) × path warmth (best connector path: effective strength staff→connector × connector→target, or direct) − investor fatigue (over cap → excluded with visible reason).
  • Scheduling: fill the window respecting max meetings/day; order operators and advisors before lead investors; group similar investors within a few days. Greedy is enough; an ILP (PuLP / OR-Tools) is a stretch.
  • Drafts: double opt-in ask to target (from staff's voice, three lines of context), and a one-page brief per meeting for the founder.

Done when the demo visit produces a full, sensible 10-day plan with reasons, one greyed investor, one fact-based exclusion, drafts and briefs.

M5Outcomes and dashboard

One-click outcome per intro; funnel metrics per visit and overall; outcomes feed back as a small prior in fit scoring (intros of this type that produced second meetings score slightly higher). Done when recording outcomes visibly changes the funnel.

M6Frontend

Four views: Graph (force-directed; edge width/opacity by effective strength; fatigued investors greyed; click node → facts with sources), Inbox (drop zone, pending diffs, accept/reject), Visit Planner (form → candidates → calendar grid filling → drafts/briefs tabs), Dashboard (funnel). Animations should make the demo legible, not decorative. Dark mode friendly.

M7Eval

  • Matching: precision@3 against the 20 ground-truth visits. Baseline: attribute filter + embedding similarity without facts or fatigue.
  • Long-horizon memory: needle-respect rate — fraction of needle cases where the system excludes or flags the investor with the correct citation. Compare retrieval mode vs full-history Wonder mode; report cost and latency for each.
  • Output a single eval/results.md table. Report honestly, including where it fails.

M8Stretch: CRM write-back

Write Persons, Relationships and Intros into a free HubSpot or Salesforce developer account via API (custom objects for Relationship and Intro). Only if M0–M7 are done by Tue evening.
